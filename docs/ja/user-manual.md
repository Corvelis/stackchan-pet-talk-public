# StackChan Pet Talk 使い方ガイド

最終更新日: 2026-07-20

このガイドは、`StackChan Pet Talk` を初めて使う方向けの手順書です。
TestFlight または Google Play クローズドテストで配布される限定ベータ版を前提にしています。

## 0. 使う前に用意するもの

必須:

- Stack-chan 本体
- Stack-chan とスマートフォンを接続する Wi-Fi 環境、または Stack-chan の SoftAP
- Stack-chan 側の WebSocket サーバー
- 会話に使う LLM。OpenAI / Gemini / OpenAI compatible API、またはローカル LLM を選びます。

Stack-chan 側の対応ファームウェアは、以下の Releases から入手できます。

https://github.com/Corvelis/stackchan-pet-fw/releases

音声や画像機能を使う場合に必要:

- Stack-chan マイク音声の binary WebSocket 送信。アプリは `SCM1` または `MIC1` ヘッダー付き PCM16 を想定します。
- Stack-chan スピーカーの binary WebSocket 受信。アプリは 16 kHz mono PCM16 を送ります。
- Stack-chan カメラの HTTP `POST /capture`。画像質問、顔登録、顔判定、カメラボタン反応で使います。
- なでなで/タッチ/振られた時の反応やカメラボタンを使う場合は、Stack-chan 側から `interaction.event` または `camera_button` の JSON イベントが届くこと。
- デバイス別キャラ、歩数連携、TTS 吹き出しを使う場合は、対応ファームウェアがデバイス情報と各機能の capability を通知できること。

ローカルモデルや辞書を使う場合は、先に [モデル/辞書/ランタイムの入手先](model-downloads.md) を確認してください。
Piper Plus 音声モデル、iPhone 用 Style-Bert-VITS2、OpenJTalk 辞書、llama.cpp GGUF、LiteRT-LM `.litertlm`、同梱モデル/ランタイムの入手先とライセンス確認事項をまとめています。
ベータ版の最短セットアップだけを確認したい場合は、
[初回セットアップ](getting-started.md) を使ってください。

## 1. このアプリでできること

`StackChan Pet Talk` は、スマートフォンから Stack-chan に接続して会話するためのアプリです。

主な機能:

- Stack-chan への SoftAP / Wi-Fi IP 接続
- テキスト入力による会話
- Stack-chan マイクを使った音声入力
- Stack-chan スピーカーへの音声出力
- ASR、TTS、LLM の設定
- 顔と声によるマスター認識
- 好感度、気分、混乱度に応じたキャラクター設定
- Android のバックグラウンド会話
- 日本語 / English の表示切り替え
- アプリ内ライセンス表示
- Stack-chan のカメラ/撮影ボタンへの反応
- TTS が使える場合の接続時挨拶ボイス
- なでなで/タッチへの反応
- 振られた時の反応と歩数に合わせた接続ボイス
- スマホカメラ、ギャラリー、Stack-chan カメラからの画像添付
- 共通またはデバイス別のキャラクター設定
- Stack-chan 同士のすれ違い通信履歴の同期とプロフィール編集
- 思い出ログと日記生成。詳しくは [思い出と日記の使い方](diary.md) を確認してください。

## 2. インストール

### iPhone

1. 招待メールまたは共有リンクから TestFlight を開きます。
2. `StackChan Pet Talk` をインストールします。
3. 初回起動時に必要な権限が表示された場合は、用途を確認して許可してください。

### Android

1. Androidベータ用のGoogleグループに参加します。
2. Google Play のクローズドテスト参加リンクを開きます。
3. `テスターになる` を押します。
4. Google Play から `StackChan Pet Talk` をインストールします。
5. Android では、通知権限やバッテリー最適化の確認が表示される場合があります。
   バックグラウンド会話を使う場合は許可してください。

## 3. 初回接続

アプリ起動後、接続準備画面で Stack-chan への接続方式を選びます。

`キャラ設定の管理`では、すべての Stack-chan で同じキャラクターを使う `共通` と、接続デバイスごとにキャラクター、好感度、思い出を分ける `デバイス別` を選択できます。

### SoftAP で接続する

1. Stack-chan を SoftAP モードにします。
2. スマートフォンを Stack-chan の Wi-Fi に接続します。
3. アプリで `SoftAP` を選びます。
4. Host は通常 `192.168.4.1`、Port は通常 `8080` です。
5. `接続` を押します。

### Wi-Fi IP で接続する

1. Stack-chan とスマートフォンを同じ Wi-Fi に接続します。
2. アプリで `Wi-Fi IP` を選びます。
3. Stack-chan の IP アドレスを Host に入力します。
4. Port を入力します。通常は `8080` です。
5. `接続` を押します。

### USB Serial で接続する（Android のみ）

1. 対応する Stack-chan と Android 端末を USB ケーブルで接続します。
2. アプリで `USB Serial` を選びます。
3. Port 欄の baud rate を確認します。通常は `921600` です。
4. `接続` を押し、USB デバイスへのアクセス確認が表示されたら許可します。

接続に成功すると会話画面に移動します。接続できない場合は、選択した接続方式に応じて Host、Port、Wi-Fi、USB ケーブルと権限、Stack-chan 側の通信設定を確認してください。

TTS が有効な場合、最初の接続画面の `接続` から接続した時だけ、接続時の挨拶ボイスを 1 つ再生します。
画面復帰時の自動再接続や、会話画面からの再接続では再生しません。

`設定 > マスター認識` の `カメラによるマスター確認` と `顔によるマスター認識` が有効で、顔プロファイルが登録済みの場合は、挨拶ボイスを選ぶ前に Stack-chan のカメラでマスター確認を行います。
マスターと判定できた場合は好感度レベルごとの接続時ボイスから選び、マスター確認できない場合は通常の `おはようございます` に戻ります。

## 4. 会話画面

会話画面では、Stack-chan の状態と会話履歴を確認できます。

画面上部:

- 接続状態
- 接続先
- 音声検出状態
- バックグラウンド会話状態

中央:

- Stack-chan の状態
- マスター認識状態
- 好感度
- 気分
- 混乱度
- 会話履歴
- エラーやイベントログ

下部:

- テキスト入力欄
- 送信ボタン
- マイクボタン
- 画像添付ボタン

テキストで話す場合は、入力欄にメッセージを書いて送信します。
音声で話す場合は、LLM と TTS の設定を済ませたあと会話画面に戻り、画面下部のマイクボタンを押します。発話が開始されたら Stack-chan に話しかけ、音声認識結果、LLM の返答、Stack-chan 本体からの返答音声を確認します。

会話履歴を削除したい場合は、会話履歴の横にある削除ボタンを押します。

画面右上のリンクアイコンで接続/切断を切り替えられます。
スマートフォンアイコンは Android のバックグラウンド会話です。
チューニングアイコンから設定画面を開きます。

アプリバー右側の `JA` / `EN` ボタンで、アプリ内表示言語を切り替えられます。

### 画像について質問する

入力欄の画像添付ボタンを押すと、画像の取得元を選べます。

- `スマホカメラ`: 新しい写真を撮影します。
- `ギャラリー`: スマートフォン内の画像を選びます。
- `デバイスカメラ`: カメラを利用できる接続中の Stack-chan で撮影します。

選択した画像は「次のメッセージに使用します」と表示され、次に送信するテキストへ添付されます。画像について回答するには、画像入力に対応した LLM と、llama.cpp の場合は対応する mmproj が必要です。
llama.cpp に渡す画像の大きさは、`設定 > LLM > VLM入力画像の最大辺` で調整できます。

このほか、マスター認識の `カメラによるマスター確認` が有効な場合、画像が必要な質問をすると Stack-chan のカメラ撮影が自動で使われます。例えば「これ見える？」「目の前にあるものを見て」などの質問で、撮影と認識が走ります。

`VLM フォールバック応答` が有効な場合、マスターの顔が一致しない時や顔が見つからない場合は、同じ画像を VLM に渡して回答します。

### Stack-chan のボタン/タッチ反応

Stack-chan からカメラ/撮影ボタンイベントが届いた場合、アプリは撮影画像について短く説明する会話を開始します。

なでなで、タッチ、pat、pet などのイベントが届いた場合は、好感度レベルに応じたボイスで反応します。`shake` または `start` イベントが届いた場合は、キャラ設定の「振られた時のボイス」から反応します。

## 5. 接続設定

`設定 > ｽﾀｯｸﾁｬﾝ接続` で接続先を変更できます。

設定項目:

- `SoftAP` / `Wi-Fi IP`
- Android の場合は `USB Serial`
- Host
- Port
- キャラ設定の管理（`共通` / `デバイス別`）
- 接続
- 切断

接続方式や IP アドレスを変えた場合は、再度 `接続` を押してください。

USB Serial は Android でのみ利用できます。USB Serial の Port 欄には baud rate として
`921600` が表示されます。Wi-Fi IP の Port とは別に扱われます。

`デバイス別`を選ぶと、対応ファームウェアから受け取ったデバイス ID を使ってキャラクター設定と思い出を切り替えます。別の Stack-chan へ接続した時に設定や日記が見えなくなったように感じる場合は、この管理モードを確認してください。

## 6. すれ違い通信

`設定 > すれ違い通信` で、Stack-chan 本体に保存されたすれ違い履歴をアプリへ同期できます。

使い方:

1. 先に `設定 > ｽﾀｯｸﾁｬﾝ接続` で Stack-chan に接続します。
2. `設定 > すれ違い通信` を開きます。
3. `今すぐ同期` を押します。
4. 同期後、すれ違いプロフィールの名前とメッセージを編集できます。
5. すれ違い履歴は相手ごとに表示されます。相手を押すと、その相手から受け取ったメッセージ履歴を確認できます。

同期時には、アプリから Stack-chan 本体へ現在時刻を送ります。履歴の時刻は端末のローカル時刻で表示されます。
本体側で時刻不明として記録された履歴は、アプリでも `時刻不明` と表示されます。

プロフィールで編集できる項目:

- 名前
- メッセージ

すれ違い通信の有効/無効やプロフィール共有設定は、アプリ画面では編集しません。

プロフィール文字数は、文字数ではなく UTF-8 byte 数で制限されます。

| 項目 | 上限 |
| --- | --- |
| 名前 | 32 bytes |
| メッセージ | 80 bytes |

日本語では、名前は約10文字、メッセージは約26文字が目安です。入力欄には byte 数が表示され、上限を超えると保存できません。

履歴の扱い:

- 履歴は相手ごとにまとめて表示されます。
- 同じ名前でも、ファームウェア側の相手識別子が違う場合は別の相手として扱われます。
- 同じ相手から同じメッセージを複数回受け取った場合、メッセージ履歴では重複表示しません。
- 相手ごとの履歴削除と、メッセージ単位の削除ができます。
- アプリで削除した履歴は、通常の差分同期では自動復元されません。

Stack-chan 本体側は保持件数に上限があります。残したい履歴は、定期的にアプリへ同期してください。

## 7. 音声AI設定

`設定 > 音声AI` で ASR と TTS を設定します。

### ASR

音声認識エンジンを選びます。

- ReazonSpeech (スマホローカル)
- gpt-4o-transcribe (クラウドAPI)
- gpt-4o-mini-transcribe (クラウドAPI)
- whisper.cpp server (ローカルPC API)
- gpt-realtime-whisper (非推奨)

OpenAI API を使う ASR を選んだ場合は、API キーの入力が必要です。
Realtime Whisper は非推奨として扱っています。通常は `gpt-4o-transcribe` または `gpt-4o-mini-transcribe` を使ってください。

#### whisper.cpp server

PC などで動かしている whisper.cpp server を使う場合は、音声認識エンジンで
`whisper.cpp server (ローカルPC API)` を選びます。

設定項目:

- `whisper.cpp URL`: whisper.cpp server の URL を入力します。既定値は `http://localhost:8090` です。

アプリは発話区間を WAV に変換し、whisper.cpp server の `/inference` API に
multipart form-data で送信します。URL に path がない場合は `/inference` を自動で補完します。
例えば `http://192.168.0.10:8090` と入力した場合は
`http://192.168.0.10:8090/inference` に送信します。

`VAD 無音判定` では、発話終了とみなす無音時間を調整できます。

### キーワード起動

キーワード起動を使うと、マイクボタンを押したあとも、開始キーワードを話すまで
会話を始めないようにできます。開始キーワードは固定ではありません。ユーザーが
自分で話した音声を登録して使います。

設定は `設定 > 音声AI > キーワード起動` から開きます。

#### 使い方

1. `キーワード起動` をオンにします。
2. `開始キーワードを登録` を開き、会話を始めたい言葉を数回録音します。
   例: `ヘイ、スタックチャン`、`会話開始` など。
3. `キーワード検出をテスト` で、登録した言葉を話して検出されるか確認します。
4. 会話画面でマイクボタンを押します。
5. 開始キーワードを話すと効果音が鳴り、その後は通常の会話に入ります。

一度会話が始まったあとは、毎回開始キーワードを言う必要はありません。
続けて話しかけるだけで会話できます。

#### 終了フレーズ

会話を終わらせる言葉は `終了フレーズ` で設定します。終了フレーズは音声認識後の
テキストで判定されます。

既定では `またね、スタックチャン`、`会話終了`、`対話終了` などが登録されています。
必要に応じて追加、削除、変更できます。複数の終了フレーズを登録できます。

会話中に終了フレーズを話すと終了音が鳴り、会話は終了します。その後は、再び開始
キーワードを話すまで会話は始まりません。

#### 調整項目

- `検出しきい値`: 小さくすると誤検出しにくくなりますが、開始キーワードを検出しにくくなる場合があります。大きくすると検出しやすくなりますが、似た発話でも反応しやすくなります。
- `Wake Word VAD 無音判定`: 開始キーワード候補の発話区切りに使う無音時間です。短くすると反応が速くなります。長くすると発話全体を取りやすくなります。
- `VAD 無音判定`: 通常の ASR 発話区切りに使う無音時間です。Wake Word 用とは別に調整できます。

Wake Word 用と ASR 用の VAD 無音判定は、どちらも 50ms から 1000ms の範囲で
10ms 単位で調整できます。Wake Word は速度重視で短め、ASR は文章の取りこぼしを
避けるため少し長めにすると調整しやすいです。

#### 登録時の注意

- 実際に使う時と近い距離、声量、話し方で録音してください。
- 短すぎる言葉や、普段の会話に出やすい言葉は誤検出しやすくなります。
- 検出しづらい場合は、同じ開始キーワードを録音し直すか、しきい値を少し上げてください。
- 誤検出が多い場合は、しきい値を少し下げるか、より長く特徴的な開始キーワードにしてください。

### TTS

音声合成エンジンを選びます。

- 無効
- Piper Plus
- Style-Bert-VITS2（iPhone CoreML、iOS のみ）
- OpenAI TTS
- Irodori TTS サーバー

Piper Plus を使う場合は、モデルファイル `.onnx` と設定ファイル `.json` を選択します。
日本語の長さ、英語の長さ、ノイズ量、ノイズ幅を調整できます。`ロボット風ボイス`を有効にすると、速度（0.5〜4.0倍）、基準 F0（50〜500Hz）、抑揚（0〜1）を調整して合成後の声を加工できます。

画面下部の `ウォームアップ用テキスト` に確認したい文章を入力し、`音声ウォームアップ`を押すと、現在の TTS 設定で再生確認できます。

スマートフォンだけで試す場合は、まず次の組み合わせから試してください。

- `.onnx`: https://huggingface.co/ayousanz/piper-plus-css10-ja-6lang/resolve/main/css10-ja-6lang-fp16.onnx
- `.json`: https://huggingface.co/ayousanz/piper-plus-css10-ja-6lang/resolve/main/config.json

iPhone の Safari では、`config.json` を普通にタップすると JSON の中身が表示される場合があります。Hugging Face の `raw` で JSON の中身を表示し、その画面を長押しして `リンク先のファイルをダウンロード` を選んでください。

つくよみちゃんのキャラクター音声も使用可能です。つくよみちゃん音声モデルを使う場合は、[音声モデル利用時の注意](voice-model-terms.md) と配布元の利用条件を確認してください。
Piper Plus の入手コマンド、OpenJTalk 辞書のダウンロード URL、配置場所は [モデル/辞書/ランタイムの入手先](model-downloads.md) を確認してください。

モデルファイルと設定ファイルは、選択時にアプリ管理領域へ取り込まれます。元ファイルを移動または削除しても、取り込み済みのコピーが使われます。

#### Style-Bert-VITS2（iPhone CoreML）

iPhone では、事前に分割 ONNX / Core ML 形式へ変換された Style-Bert-VITS2 モデルを端末内で実行できます。

設定項目:

- `BERT フォルダ`: 変換済み BERT モデル一式を含むフォルダです。
- `VITS2 フォルダ`: 1つ以上の変換済みボイスを含むフォルダです。
- `ボイス`: VITS2 フォルダ内から検出されたボイスです。
- `Speaker ID`: 使用する話者 ID です。
- `スタイル`: `Neutral` など、モデルに含まれるスタイル名です。
- `話速`: 0.5〜2.0倍で調整します。

BERT と VITS2 は個別に選択し、初回選択時にアプリ内へコピーします。通常配布されている未変換モデルをそのまま選択することはできません。配布者が用意した対応モデルを使用し、モデルごとのライセンスと利用条件を確認してください。

#### OpenAI TTS

OpenAI TTS を使う場合は、TTS エンジンで `OpenAI TTS` を選びます。

設定項目:

- `OpenAI TTS API キー`: OpenAI の TTS API キーを入力します。目のアイコンで表示/非表示を切り替えられます。
- `TTS Base URL`: 通常は `https://api.openai.com/v1` のままで使います。
- `TTS モデル`: `gpt-4o-mini-tts` などを選びます。
- `TTS ボイス`: 選択式です。モデルに対応するボイスだけが表示されます。
- `話し方の指示`: 対応モデルに渡す話し方の指示です。
- `音声形式`: 通常は `PCM16` のままで使います。
- `話速`: 音声の速度を調整します。
- `発話の間`: 句読点で区切った音声セグメントの再生間隔です。既定値は `50ms` です。

OpenAI TTS と Irodori TTS は、LLM の返答を句読点中心に区切り、再生中に次の音声を先読み合成します。
順番は保ったまま再生され、返ってきた音声の前後にある無音はアプリ側で軽くトリムします。
発話が詰まりすぎる場合は `発話の間` を大きくし、間が長い場合は小さくしてください。

対応ファームウェアが `display.speech_bubble.v1` を通知する場合、分割された発話テキストを Stack-chan の吹き出しへ送り、音声の開始・終了・キャンセルに合わせて表示を同期します。

#### Irodori TTS サーバー

Irodori TTS を使う場合は、事前に PC などで Irodori TTS serverを起動し、TTS エンジンで `Irodori TTS サーバー` を選びます。

設定項目:

- `TTS Base URL`: Irodori TTS サーバーの OpenAI 互換 API URL を入力します。例: `http://192.168.0.10:8088/v1`
- `API キー（任意）`: サーバー側で認証を要求していない場合は空欄で構いません。
- `TTS モデル`: 通常は `irodori-tts` のままで使います。
- `TTS ボイス`: `none` または登録済みボイス名を指定します。
- `サーバーからボイス一覧を取得`: サーバーに登録されているボイス一覧を取得し、選択肢に反映します。ボイスがない場合は `none` を使います。
- `アップロード時のキャラ名`: 参照音声をアップロードする時のボイス名です。空欄の場合は音声ファイル名が使われます。
- `参照音声をアップロード`: クライアント側から参照音声ファイルをサーバーへ登録します。同じ名前が既にある場合は置き換えます。
- `音声形式`: 通常は `WAV` のままで使えます。`PCM16` を使う場合は PCM サンプルレートも設定します。
- `話速`: 音声の速度を調整します。
- `Irodori num_steps`: Irodori TTS の生成ステップ数です。既定値は `20` です。値を下げると速くなりやすく、値を上げると品質が上がる場合があります。
- `発話の間`: 句読点で区切った音声セグメントの再生間隔です。既定値は `50ms` です。

`TTS ボイス` が `none` の場合、参照音声を固定しないため、声が毎回変わることがあります。
同じ声に寄せたい場合は、参照音声をアップロードして、そのボイス名を選んでください。


TTS の直前には、攻撃、政治・宗教・思想への呼びかけ、刺激の強い表現に該当するかを軽量な語彙ルールで確認します。
該当した場合、会話画面のテキスト表示は残したまま音声合成だけをスキップします。

## 8. LLM設定

`設定 > LLM` で会話に使う LLM を設定します。

選べるプロバイダー:

- OpenAI compatible API
- OpenAI API
- Gemini API
- llama.cpp
- LiteRT-LM

API 型のプロバイダーでは、Base URL、モデル名、API キーなどを設定します。
ローカル LLM では、モデルファイルを選択し、最大トークン数、temperature、topK、topP、コンテキストサイズ、バッチサイズ、スレッド数などを調整します。

Base URL には `http://192.168.0.10:8080/v1` のように PC の LAN IP を指定してください。

`LLMに渡す過去会話` では、LLM へ渡す会話履歴の量を選べます。
対応モデルでは Thinking 制御も設定できます。

ローカル LLM の `Prefix KV cache` は、以前の会話履歴やシステムプロンプトの一部を先に読み込んでおき、次の返答開始を速くするための設定です。
`設定 > LLM` のローカル LLM 設定でオン/オフできます。対象は llama.cpp と LiteRT-LM です。
オンにすると応答開始が速くなる場合がありますが、会話後に先読み処理が走るため端末の CPU / GPU / メモリ使用量が増えることがあります。発熱、バッテリー消費、または出力の不安定さが気になる場合はオフにしてください。
画像付き会話では、このキャッシュを使わず通常の生成に戻る場合があります。
この設定をオンにすると、会話履歴の使用量はローカル LLM の実行方式に合わせて自動調整されます。

llama.cpp では GGUF モデルファイルを選びます。画像対応モデルを使う場合は mmproj ファイルも選びます。
`VLM入力画像の最大辺` では、`元のサイズ`、`128px`、`256px`、`384px`、`512px`、`768px`、`1024px`、`1536px`、`2048px` から選べます。既定値は `2048px` です。画像は縦横比を維持して指定値まで縮小され、指定値より小さい画像は拡大されません。小さくすると処理時間とメモリ使用量を抑えられますが、細部や小さい文字の認識精度が下がる場合があります。`元のサイズ` を選ぶとアプリ側での事前縮小を行いませんが、モデルや mmproj の画像処理でさらに変換される場合があります。
LiteRT-LM では現在のアプリ実装上、`.litertlm` のモデルファイルを選びます。`.task` はこの画面では選択対象外です。
スマートフォンでローカル LLM を試す場合は、まず Gemma 4 E2B の `gemma-4-E2B-it.litertlm` を使う想定です。

- Repository: https://huggingface.co/litert-community/gemma-4-E2B-it-litert-lm
- 直接ダウンロード: https://huggingface.co/litert-community/gemma-4-E2B-it-litert-lm/resolve/main/gemma-4-E2B-it.litertlm

ローカル LLM は CPU / GPU を選択できます。(Android x llama.cppはCPUのみ)
llama.cpp の GPU 利用時は GPU レイヤー数を調整できます。Metal でクラッシュする場合は値を下げてください。

llama.cpp と LiteRT-LM にはウォームアップボタンがあります。モデルが正しく読み込めるか確認したい時に使います。
LiteRT-LM では `VLM 画像ウォームアップ` を有効にすると、画像入力を含む初期化確認を行います。

選択した GGUF、LiteRT-LM、mmproj はアプリ管理領域へ取り込まれます。`取り込んだLLMファイルを削除`を押すと、アプリ内のローカル LLM ファイルと保存済みモデルパスをまとめて削除します。ファイルアプリなどにある元ファイルは削除しません。


## 9. マスター認識

`設定 > マスター認識` で、顔と声によるマスター認識を設定します。

重要:

- マスター認識はキャラクター反応用の機能です。
- 顔画像や音声そのものではなく、認識用の特徴量を保存する設計です。

設定できる項目:

- カメラによるマスター確認
- VLM フォールバック応答
- 顔によるマスター認識
- 声によるマスター認識
- 顔認識しきい値
- 声認識しきい値
- 登録、判定チェック、登録削除
- マスターを見つけた時の反応
- マスター認識に失敗した時のプロンプト

顔登録では、Stack-chan のカメラにマスター 1 人だけが写るようにしてください。
声登録では、普段の声で数秒話してサンプルを登録します。

顔は最大 3 サンプルまで登録できます。顔画像そのものは保存せず、認識用の特徴量を保存します。
声は 3 サンプル以上で保存できます。録音音声そのものは保存せず、平均特徴量を保存します。

`マスターを見つけた時の反応` では、好感度レベルごとにマスター発見時のボイスを編集できます。
`{masterName}` と書くと、キャラ設定のマスター呼び名に置き換わります。

## 10. キャラ設定

`設定 > キャラ設定` で、Stack-chan の話し方や反応を調整できます。

タブ:

- 基本
- 好感度
- ボイス反応

基本タブ:

- マスター呼び名
- ベースプロンプト
- 気分 70 以上のプロンプト
- 混乱度 60 以上のプロンプト

好感度タブ:

- 好感度プロンプトの ON / OFF
- 好感度レベルごとのシステムプロンプト

ボイス反応タブ:

- 「振られた時のボイス」
- 好感度レベルごとの「なでられた時のボイス」
- 好感度レベルごとの「接続した時のボイス」
- 「歩数に合わせた接続ボイス」の ON / OFF と歩数レンジごとの候補
- 反応ボイスの追加と削除

変更後は `保存` を押してください。
現在のタブだけ初期値に戻したい場合は `デフォルトに戻す` を押します。

ここで設定した「なでられた時のボイス」は、Stack-chan からなでなで/タッチ系イベントが届いた時に使われます。
「振られた時のボイス」は、Stack-chan から `shake` / `start` イベントが届いた時に使われます。
「接続した時のボイス」は、最初の接続画面から接続した時の挨拶に使われます。カメラによるマスター確認が有効な場合は、挨拶前の判定結果を反映してから好感度レベル別の候補を選びます。
「歩数に合わせた接続ボイス」は、1000歩を超え、同じ日の前回接続時から歩数レンジが変わった時に使われます。対応ファームウェアから歩数情報を受信できる必要があります。
マスター発見時のボイスは `設定 > マスター認識 > マスターを見つけた時の反応` から編集します。

## 11. バックグラウンド会話

Android では、会話画面上部のスマートフォンアイコンからバックグラウンド会話を有効にできます。

有効化時に通知権限やバッテリー最適化の確認が表示される場合があります。
バックグラウンド会話を安定して使うには、通知権限を許可し、必要に応じてバッテリー最適化の対象外にしてください。

バックグラウンド会話を止める場合は、同じボタンをもう一度押すか、通知から停止します。

## 12. 思い出と日記

会話画面の `思い出` アイコンから、日付ごとのログ、写真、日記を確認できます。

対応ファームウェアから歩数を受信している場合は、その日の歩数も表示されます。写真の詳細画面では、端末のギャラリーへ保存できます。`デバイス別`キャラを使っている場合、思い出と日記は現在接続しているキャラクターごとに表示されます。

日記は、選択日の会話や写真ログが5件以上ある場合に作成できます。`設定 > 思い出と日記` では、自動生成、日記の区切り時刻、マスターとの会話だけを使う設定、写真保存、事前要約、日記プロンプトを調整できます。

詳しい使い方は [思い出と日記の使い方](diary.md) を確認してください。

## 13. デバッグ

`設定 > デバッグ` では、現在のセッションだけ好感度を一時的に変更できます。

歩数挨拶の確認用に、同じ歩数レンジでも接続ごとに再生する設定があります。

これは動作確認用です。通常利用では変更する必要はありません。

## 16. 困ったとき

接続できない:

- スマートフォンと Stack-chan が同じネットワークにいるか確認します。
- SoftAP の場合はスマートフォンが Stack-chan の Wi-Fi に接続されているか確認します。
- Host と Port を確認します。
- Stack-chan 側の WebSocket サーバーが起動しているか確認します。

音声入力できない:

- マイクボタンが有効になっているか確認します。
- Stack-chan マイクが利用できる状態か確認します。
- ASR 設定と API キーを確認します。
- ReazonSpeech を使う場合は、ベータビルドに ReazonSpeech と Silero VAD のモデルが同梱されているか、配布者に確認します。

音声が出ない:

- TTS が無効になっていないか確認します。
- Piper Plus のモデルファイルと設定ファイルを確認します。
- Piper Plus で日本語 OpenJTalk 系モデルを使う場合は、OpenJTalk 辞書が同梱または配置されているか確認します。
- Stack-chan スピーカー接続を確認します。

LLM が返答しない:

- LLM プロバイダー、モデル名、API キー、Base URL を確認します。
- ローカル LLM の場合はモデルファイルの場所を確認します。
- OpenAI compatible API をスマートフォン実機から使う場合は、Base URL が `localhost` ではなく PC の LAN IP になっているか確認します。
- LiteRT-LM の場合は `.litertlm` ファイルを選んでいるか確認します。
- 会話画面のエラー表示を確認します。
